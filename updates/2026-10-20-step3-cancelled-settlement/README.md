# 3단계 검토: 취소관련 정산 제외·파일 불러오기
기준일: 2026-10-20
1·2단계는 사용자 검토 완료. 3단계 사용자 검토 대기.

## 원인과 변경
처리현황의 '취소관련'이 기존 허용 목록에 없어 주문 파일 전체를 차단했습니다.
취소관련을 명시적인 제외 상태에 추가했습니다. 해당 행은 취소·환불 내역으로 분류하며 판매 수량·유효 주문 건수·정산 기준 매출·수수료·지급 대상에서 제외합니다.
원본 처리현황은 엑셀 상세에 그대로 보존합니다. 원래의 행 번호·상품·수량·금액을 변경하거나 행을 삭제하지 않습니다.
별도 환불 지급을 실행하는 기능이 아니라 정산 대상에서 제외하는 처리입니다.

## 유지한 기준
- 교환완료는 매출 포함, 취소·입금대기·반품완료·환불완료는 제외.
- 부분취소·부분환불 및 미확정 상태는 임의로 전액 차감하지 않고 기존 확인 오류를 유지.
- 수수료율 10/15/20%, 개인 세금 공제·사업자 미공제, 세목별 버림, 쿠폰 미계산 기준은 변경하지 않음.
- 정산 기준 매출에서만 제외. 기존 사용자 지정 '일정표 매출=주문금액, 판매건수=유효 주문번호 건수' 연결 규칙과 합산 확인은 변경하지 않음.
- 출력의 취소건 차감 수식과 취소 행 강조는 같은 상태 판별 결과를 사용.
- 1단계 날짜 클릭 등록·2단계 한 줄 일정 바는 유지.
- 일정·매출·DB 자료 및 회사 서버는 변경하지 않음.

## 검증
제공 샘플에서 기존 오류를 재현하고 정상 불러오기와 취소 행 제외를 확인했습니다.
개인/사업자 × 수수료 10/15/20%를 독립 계산과 대조했습니다.
상태 33개 회귀 검사와 전부 취소 시 지급액 0 검사를 통과했습니다.
개인·사업자 전달용 출력의 수식·캐시·재계산·취소 행 색상·쿠폰 열 부재를 확인했습니다.
검증용 주문 자료·출력 파일·구매자 정보·실제 금액은 이 공개 저장소에 포함하지 않습니다.
회귀 검사는 저장소 루트에서 node updates/2026-10-20-step3-cancelled-settlement/status-regression.cjs 로 실행합니다.

## 회사 PHP 서버 적용
검토용 public/index.php에는 회사 서버의 로그인·DB 연결·저장 코드가 없습니다.
**회사 서버 파일을 이 PHP 전체로 덮어쓰지 마세요.**
- 1·2단계가 이미 적용됐다면 stage3-only.patch의 상태 목록/도움말 변경만 병합.
- 아직 1단계부터 적용하지 않았다면 stage1-to3.patch에서 세 단계 변경분을 확인해 병합.
- 두 패치를 함께 적용하지 않음. 패치 경로는 GitHub 검토본 기준이므로 개발자가 실제 서버 파일에 맞춰 병합.
- 회사 서버에서 로그인·DB 저장 유지, 취소 포함 주문 불러오기, 제외 금액·지급액, 전달용 엑셀을 다시 확인.
원본 샘플은 검증 과정에서 수정하지 않았습니다. PHP 실행기가 없어 PHP 엔진 실행 검사는 수행하지 않았습니다.

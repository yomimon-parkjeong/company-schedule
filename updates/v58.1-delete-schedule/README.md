# v58.1 일정 삭제 — v58 전용 변경분

v58에서 일정 삭제와 버전 표시만 추가했습니다. 기존 CSV 분류·날짜·색상·특이사항·매출·정산 계산은 변경하지 않았습니다. 회사 서버/DB에는 적용하지 않았습니다.

## 사용자 흐름
기존 일정 클릭 → 편집 창 하단 빨간 `일정 삭제` → `이 일정을 삭제하면 다시 복원 못합니다.` → 취소/삭제 → 삭제 시 `삭제 완료` 알림.

- 새 일정 등록 창에는 삭제 버튼이 없습니다.
- 취소 또는 ESC는 편집 창과 저장 전 입력값을 유지하고 삭제 버튼으로 초점을 돌립니다.
- 삭제는 선택한 저장 일정에만 적용하며, 편집 중인 미저장 내용은 저장하지 않습니다.
- 삭제 후 월간/목록/주간, 담당자·주차 집계, 매출·SKU 집계, 정산 연결 표시를 현재 일정 배열로 다시 계산합니다. 정산 원본 주문 자료는 삭제하지 않습니다.
- 다른 일정과 취소 상태는 변경하지 않습니다. 이전 선택이 바뀌거나 해당 일정이 교체되면 삭제를 중단합니다. 중복 클릭도 한 번만 처리합니다.
- 자체 실행 취소/휴지통은 없습니다. 외부 원본 CSV까지 삭제하는 기능은 아니므로 같은 CSV를 다시 반영하면 동일 원본을 신규 일정으로 다시 생성할 수 있습니다.
- 상단과 페이지 제목에 v58.1을 표시했습니다.

## 운영 적용 — 필수 확인
이 저장소의 PHP는 화면 시안을 제공하는 파일입니다. DB 삭제 API·인증·공용 저장이 들어 있지 않습니다. GitHub 미리보기와 동봉 preview/index.php의 삭제는 현재 페이지 메모리에서 처리되며 새로고침 시 원래 초기 상태로 돌아갑니다.

회사 운영 index.php를 동봉 파일로 통째로 덮어쓰지 마세요. 개발자는 정상 운영 중인 v58을 백업하고 v58-to-v58.1.patch의 추가 부분만 병합합니다. 실제 테이블명/서버 코드가 없으므로 특정 DB 요청을 임의로 만들지 않았습니다.

운영 영구 삭제를 연결할 위치는 confirmScheduleDelete 안의 schedules.splice 직전입니다.
1. 확인창에서 삭제한 일정의 실제 서버 식별자/sourceId를 사용해 인증된 삭제 API를 호출합니다.
2. 서버에서 세션 권한·CSRF·일정 식별자를 검증하고, 선택 일정 및 그 일정에 소속된 매출 연결 이력만 처리합니다. 정산 원본 주문 자료/다른 일정은 삭제하지 않습니다.
3. 삭제 요청 중 버튼을 비활성화하고, 서버 성공 응답을 받은 뒤에만 splice·창 닫기·재계산·완료 알림을 실행합니다. 서버 실패 시 일정은 유지하고 확인창에 오류를 표시합니다.
4. 새로고침과 다른 직원의 접속에서도 삭제 결과가 유지되는지 확인합니다. CSV 재입력 시 재생성을 막아야 한다면 별도 삭제 식별자 정책을 DB에 적용해야 합니다.

API 연결이 끝나기 전까지 화면의 '삭제 완료'를 운영 DB 영구 삭제 확인으로 판단하면 안 됩니다. 운영 업로더/인증/DB 관련 코드는 이 저장소에 없으므로 이번 검증에 포함되지 않았습니다.

## 검증
- 공식 PHP 8.5.11 포터블 실행기를 D드라이브 검증 폴더에서만 사용했습니다. 공식 SHA256 검증 후 실행했으며 시스템/회사 PHP 설정은 변경하지 않았습니다.
- short_open_tag=0/1 각각 PHP 문법 검사 통과 및 실제 PHP 출력과 Pages HTML 일치.
- 로컬 PHP 서버의 가상 CSV 일정으로 취소/ESC 유지, 삭제 완료, 다른 일정 보존, 월간3→2건·매출100000→80000 재계산, 목록 제거 및 주간 삭제 후 빈 주 표시 확인.
- 신규 등록창 삭제 버튼 없음, 경고창 취소 기본 포커스, 편집창 복귀 포커스, 중복/잘못된 대상 삭제 방지 검사.
- 기존 CSV1679행 분류 검사, 매출·특이사항 보존 검사와 정산 상태33건 통과. 브라우저 콘솔 오류 0건.
- 실제 사내 일정·DB·정산 파일은 변경하지 않았으며 삭제 테스트에는 가상 일정만 사용했습니다. 테스트용 일정은 private QA 사본에만 넣고 공개 실행본은 초기0건입니다.

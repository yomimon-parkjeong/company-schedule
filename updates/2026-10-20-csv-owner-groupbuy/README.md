# CSV 담당자 기준 공동구매 분류 · PHP XML 호환

## 사용자 확인 기준
사이트 행사(S), 담당자 미지정(U/공란)을 제외하고 담당자가 지정된 원본 CSV 일정은 공동구매입니다. 페이백도 별도 업무 유형이 아닌 기존 내용으로 보존합니다.

- CSV 가져오기의 담당자 키가 S/U/공란이 아니면 type=공동구매를 우선 적용합니다. 등록된 사용자 추가 담당자도 포함합니다. S/U/공란은 기존 분류를 유지합니다.
- 이 정책은 CSV 가져오기 기준입니다. 수동 등록·편집 화면의 유형 선택을 강제로 바꾸지는 않습니다.
- 동일 sourceId·동일 CSV라도 옛 분류가 남아 있으면 type/typeClassification을 갱신합니다. 기존 매출·특이사항·색상·기간과 showNotesOnCalendar는 보존합니다. CSV 담당자가 있는 행의 업무유형은 이번 승인 기준을 우선하므로 해당 유형의 과거 수동 수정도 공동구매로 바뀝니다.
- 종일 여부 allDay는 TRUE/FALSE 및 true/false를 모두 받습니다.
- 취소 상태는 유지하며 취소된 일정은 기존 공구 통계에서 제외합니다.

## 일정 바의 ‘~의 일정’
이 문구는 CSV 제목에 없으며 UI의 event-owner 렌더링에서 붙는 표기입니다. CSV를 재입력해도 화면 코드는 바뀌지 않습니다. 앞선 2단계 event-owner 제거와 월간34px/주간40px CSS 변경을 회사 서버에 병합해야 합니다. 이번 누적 패치에는 포함되어 있습니다. 담당자 필터·집계·상세·등록 편집의 담당자 정보는 남깁니다.

## 회사 서버의 PHP 오류
확인 당시 회사 페이지는 index.php 692행의 unexpected identifier "version" 오류를 반환했습니다. 같은 줄의 엑셀 출력용 XML 선언이 short_open_tag 환경에서 PHP 여는 태그로 오인되는 현상과 일치합니다. 서버 설정과 운영 소스 확인은 담당 개발자가 해야 합니다.

검토용 PHP의 XML 선언 20곳을 JavaScript Unicode 이스케이프로 표현해 PHP가 코드로 해석하지 않게 했습니다. JS 실행 후 엑셀 템플릿 내용은 수정 전후 동일함을 검사했습니다. PHP 공식 참고: https://www.php.net/manual/en/language.basic-syntax.phptags.php

## 병합
- 최신 특이사항 표시 선택까지 반영된 서버에는 csv-owner-and-xml.patch만 참고해 병합합니다.
- 이전 단계도 없으면 cumulative.patch에서 1~3단계·특이사항 표시·이번 변경 전체를 확인합니다. 두 패치를 동시에 적용하지 않습니다.
- 검토용 PHP는 회사 DB/로그인 코드가 없는 원본입니다. 운영 파일 전체를 교체하지 말고 변경분만 병합하세요. 비밀번호나 DB 연결 정보는 이 자료에 없습니다.
- company CSV importer가 별도 구현되어 있으면 그 경로에도 담당자 기반 우선 분류, 동일 CSV 재분류, allDay 대소문자 처리를 적용해야 합니다.
- 서버에는 먼저 PHP 오류 수정과 앞선 화면 수정들을 병합한 뒤 제공 CSV를 미리보기·반영하세요. DB 백업과 운영 검증은 담당 개발자가 수행해야 합니다.

## 검증
실제 입력 1679행을 읽고 검토용 입력 함수로 검증했습니다. 담당자 지정 869행을 공동구매로 분류했으며 페이백 문구 31행도 포함합니다. 나머지810행의 업무유형은 수정 CSV에서 유지했습니다. CSV는 업무유형684칸과 allDay 대소문자1679칸만 바꾸고 다른 컬럼 값은 원본과 대조했습니다. 원본 파일은 변경하지 않았습니다.

JS 문법·동일 CSV 재분류·매출/특이사항/표시설정 보존·엑셀 템플릿 동일성·기존 정산 상태33건을 검증했습니다. 회사 PHP 런타임/DB에 적용하거나 회사 CSV를 재업로드하지 않았습니다. 실제 일정 CSV는 이 공개 업데이트에 포함하지 않습니다.

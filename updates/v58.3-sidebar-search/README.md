# v58.3 왼쪽 전체 기간 검색

왼쪽 일정 검색에 이름의 일부를 입력하면 현재 월·주차와 관계없이 일치하는 일정이 모두 나옵니다. 예: `봄동`으로 `봄동맘`을 찾습니다. 2년 또는 특정 연도 제한을 두지 않습니다.

## 화면 동작
- 상단 월간 도구의 검색창을 왼쪽으로 이동했습니다. 중복 검색창은 두지 않습니다.
- 입력하면 별도 검색 결과 화면으로 전환합니다. 전체 기간·전체 담당자·전체 유형을 대상으로 하며 달력의 담당자·유형·매출 필터는 검색에 적용하지 않습니다.
- 일정명, 닉네임(이름), 상품, 담당자, 거래처를 부분 일치로 검색합니다. 대소문자와 전각 영문을 정규화하고, 공백으로 구분된 여러 단어는 모두 포함해야 합니다. 의미 유사어·오타 추정 검색은 아닙니다.
- 시작일 최신순이며 전체 일치 건수를 표시합니다. 50건씩 페이지를 나누어 볼 수 있고 검색 기간을 잘라내지 않습니다.
- 결과를 누르면 기존 상세·편집 팝업을 엽니다. 수정·삭제 후 결과가 갱신됩니다. 검색 지우기·일정표로 돌아가기는 이전 월간/목록/주차 화면을 복원합니다.
- 표시를 해제한 특이사항, sourceCsv, originalTitle은 숨은 검색 대상에 넣지 않습니다. 표시를 허용한 특이사항만 같은 공개 표시 기준으로 검색합니다. 결과는 텍스트 노드로 출력합니다.

## GitHub 미리보기와 회사 DB의 구분
GitHub Pages는 CSV를 직접 반영해 현재 페이지에 불러온 일정 전체를 검색합니다. 초기 일정은 0건이고 서버 DB와 연결되어 있지 않습니다. CSV 저장·DB 조회·신규/편집/삭제 영구 저장은 이번 변경에서 구현하지 않았습니다.

회사 운영본에는 검토용 PHP 전체를 덮어쓰지 마세요. `v58.2-to-v58.3.patch`는 GitHub v58.2 검토본 기준이며, 회사 운영본에 추가된 DB·로그인·업로더 코드를 보존하면서 해당 UI와 검색 함수만 병합합니다. 실제 회사 서버는 이번에 변경하지 않았습니다.

## 운영 DB 연결 시 필요한 조건
- 인증된 검색 API에서 직원의 권한 범위 내 전체 기간을 검색합니다. 현재 달 조회 결과만 검색하거나 2년 조건을 추가하지 않습니다.
- DB 구조·API 주소는 실제 운영 코드를 받은 후 연결합니다. 기존 조회 API의 월 제한을 해제하는 방법 또는 별도 검색 API 여부는 운영 구조에 맞춰 선택합니다.
- 부분 일치·대소문자/문자 정규화·다중 단어 조건을 미리보기와 일치시키고, SQL은 매개변수로 바인딩합니다. 사용자가 입력한 `%`, `_` 등은 리터럴 문자로 검색되도록 처리합니다.
- 전체 건수와 50건 단위 페이지를 제공하고 시작일·종료일·고유 ID로 안정적으로 정렬합니다. 빠른 입력 시 이전 검색 응답이 최신 결과를 덮어쓰지 않도록 취소 또는 요청 순서를 확인합니다.
- DB 검색도 비공개 특이사항과 과거 원문에서 숨은 일치를 만들지 않습니다. 이름·상품 표시, 취소 상태, 기존 일정 ID는 보존합니다.
- 선택한 결과는 기존 ID로 상세 조회·편집·삭제에 연결하고 DB 성공 응답 이후 결과를 갱신합니다. 검색 자체는 저장 데이터를 변경하지 않습니다.

## 검증
`node tools/verify-sidebar-search.cjs`로 부분 일치, 2020~2035 기간, Unicode·다중 단어·특수문자, 숨긴 메모/과거 원문 제외, 원본 객체 불변, 초기 0건과 JS 문법을 확인했습니다. 가상 65건으로 결과 편집 후 갱신·61건 페이지 이동·검색 지우기·주차 복귀·브라우저 오류 0건을 확인했습니다. PHP 8.5.11 short_open_tag 0/1 문법 및 HTML 출력 일치와 이전 이름 표시 1,679행 검증도 통과했습니다. 실제 업무 일정이나 검증용 가상 데이터는 공개 실행본에 내장하지 않습니다.

# v58.2 인플루언서 닉네임(이름) 표시

## 원인과 수정
CSV 이름이 삭제된 문제가 아니라 openingFields가 괄호 앞의 닉네임만 뽑아 화면 제목에 사용하던 표시 문제입니다.

- 내부 nickname은 기존처럼 이름 없는 계정 키로 유지합니다. 정산 계정 매칭·검색·정렬·상품 집계 기준은 유지합니다.
- 표시용 displayName을 추가하여 현재 influencer 또는 현재 title의 일치하는 닉네임 뒤 괄호 이름을 보여줍니다. 예: @sample.a(예시A) : 와우펜.
- 달력 바·툴팁·접근성 이름·상세 제목·선택 정보·목록·주차 상세/복사·SKU 공구 목록·일정별 매출 내보내기에 같은 표시 이름을 사용합니다.
- 전각 괄호도 일반 괄호로 표시합니다. 이름이 없으면 닉네임만 표시하며 추정 이름을 생성하지 않습니다. 이름 변경 후 저장도 유지합니다.
- specialNotes, sourceCsv, originalTitle에서 이름을 끌어와 붙이지 않습니다. 현재 제목에서 특이사항 접미부를 제거하고 이름을 확인하며, 숨긴 특이사항을 이름으로 노출하지 않습니다.
- 이미 CSV에 저장된 influencer/title의 이름을 이용하는 표시 수정이므로 CSV를 다시 가공할 필요가 없습니다. 새 화면을 연 뒤 기존 CSV를 수동 반영하면 됩니다.
- 원본 CSV·저장 일정 필드·매출 금액·기간·색상은 변경하지 않습니다. v58.1 삭제 흐름, 특이사항 표시 설정과 이전 CSV 분류 개선을 유지합니다.
- 상단과 페이지 제목에 v58.2를 표시합니다.

## 운영 병합
- 현재 운영 화면이 v58.1이면 v58.1-to-v58.2.patch만 병합하세요.
- 현재 운영 화면이 v58이면 v58-to-v58.2.patch로 삭제 기능과 이름 표시를 함께 병합할 수 있습니다. 두 패치를 동시에 적용하지 않습니다.
- preview/index.php는 DB/로그인/소스 업로더가 없는 검토용 PHP입니다. 회사 운영 index.php를 이 파일로 통째로 교체하지 마세요. 회사 코드의 해당 함수와 표시 부분만 개발자가 병합해야 합니다.
- v58.1의 DB 삭제 API 연결 필요 사항은 그대로입니다. 이번 변경은 별도의 DB 구조 변경이나 이름 데이터 마이그레이션을 요구하지 않습니다. GitHub 미리보기의 편집/삭제는 현재 페이지 메모리에서만 유지됩니다.

## 검증
- 기존 1679 CSV 행에서 수정 전후 nickname·product가 동일하고 원본 객체가 변하지 않음을 확인했습니다. 표시 가능한 이름은 현재 기록에서만 추출합니다.
- 이름 있는/없는 일정, 제목에만 있는 이름, 전각 괄호, 점이 포함된 닉네임, 현재 이름 우선, 숨긴 특이사항 제외, 정산 계정 매칭을 검사했습니다.
- 로컬 PHP 화면에서 월간34px·주간40px 유지, 상세 제목/입력란 이름 일치, 이름 편집 저장, 목록·주차 상세 이름 표시, 기존 삭제 버튼 유지와 브라우저 오류0건을 확인했습니다.
- PHP 8.5.11 short_open_tag=0/1 문법 검사 및 실제 PHP 출력과 Pages 일치를 확인했습니다. 이전 삭제 보호 검사·CSV 입력1679행·정산 상태33건 검사도 통과했습니다.
- 회사 서버/DB는 변경하지 않았습니다. 실제 개인정보는 공개 미리보기와 검증 스크린샷에 넣지 않았고, 공개 실행본은 초기 일정0건입니다.

# v59 사업자명과 상세 매출 기록 미리보기

GitHub Pages에서 검토할 클라이언트 시안입니다. 회사 운영 PHP와 Firebase에는 적용하지 않았습니다. 이 폴더나 developer-empty의 PHP를 회사 운영 index.php로 통째로 교체하지 않습니다. 기존 운영의 Firebase 저장 API·비공개 설정·직원 데이터는 유지해야 합니다.

## 화면

- 정산 파일 선택 후 사업자를 선택하면 사업자명을 입력합니다. 일반 개인에는 표시하지 않습니다. 파일마다 사업자명을 확인하며 취소·손상 파일은 기존 정산을 유지합니다.
- 정산 미리보기의 사업자명은 SKU 상세에서 닉네임 오른쪽에 표시되고 전달용 사업자 엑셀의 정산 정보 영역에도 들어갑니다. 주문 내역의 9컬럼과 기존 계산은 유지합니다.
- 이미 일정 매출을 반영한 자료는 사업자명만 확인 후 수정할 수 있습니다. 판매건수·주문금액·자료 식별값은 다시 합산하거나 변경하지 않습니다.
- 일정 바를 눌러 연 상세 편집창의 매출 아래에서 **상세 매출 기록** 버튼을 누릅니다. 별도 팝업에서 같은 닉네임의 누적 기록 또는 이 일정의 기록을 조회합니다.
- ×·팝업 바깥 클릭·ESC·돌아가기 버튼은 기록 팝업만 닫습니다. 부모 상세 편집창은 열린 상태를 유지하며 입력값·스크롤·버튼 초점을 보존합니다. 이 팝업의 열기·조회·닫기는 저장 동작을 하지 않습니다.
- 기록의 주문 기간이 같은 연월·차수에 속하면 `2026년 10월 2차`, `2026년 11월 1차`처럼 표시합니다. 여러 차수나 월을 넘긴 자료는 원래 날짜와 ‘정산 기간 확인 필요’를 표시하며 임의 분리하지 않습니다.

## 기록과 집계

새로 반영하는 정산에는 계산 당시 정산 기준 매출·세전 수수료·세금·지급 예정액을 별도 정보로 연결합니다. 지급 상태의 초기값은 지급대기이며 정산 반영을 실제 지급 완료로 처리하지 않습니다. 과거에 저장되지 않은 수수료·지급 정보는 추정하지 않고 미등록으로 표시합니다.

같은 닉네임의 일정은 정확히 일치하는 계정명으로 연결하며 사업자명이나 이름 일부만으로 다른 인플루언서를 합치지 않습니다. 조회 범위는 현재 페이지에 불러온 일정입니다. 누적 주문금액은 해당 일정들의 저장된 주문금액 합계이며 취소·반품 차감 전 기준입니다. 수수료·지급액은 연결된 정산 기록에 값이 있는 범위만 합산하고 등록 현황을 함께 표시합니다.

월 정산 요약과 SKU/인플루언서 지급수수료 표시는 이후 사용자 승인으로 [누락 보완 미리보기](../v59-settlement-summary/README.md)에 추가했습니다. 실제 지급 완료를 입력하는 관리 기능, 엑셀 이력 내보내기, 주문 일부가 겹치는 서로 다른 자료의 중복 원장은 계속 별도 후속 범위입니다.

## 운영 연결 시 필요한 별도 작업

이 미리보기의 변경은 페이지 메모리에만 유지됩니다. 초기 일정은 0건이며 CSV는 수동으로만 반영합니다. 공개 페이지에 실제 일정이나 가상 테스트 일정을 내장하지 않습니다. 새로고침하면 입력한 일정과 정산 기록이 초기화됩니다.

운영 PHP 연결은 기존 v58.4의 로그인·세션·CSRF·저장 버전·중복 방지를 유지하면서 recipient, financial, paymentStatus 같은 추가 정산 정보를 검증·저장하도록 별도로 구성해야 합니다. 사업자명만 변경하는 요청은 매출 누적과 분리해야 하며, 구버전 화면에서 기존 일정 수정 시 새 정보가 지워지지 않아야 합니다. 기존 DB를 일괄 갱신·복원·초기화하지 않습니다.

## 검증 범위

초기 18개 로컬 상호작용 모델 검사는 숨겨진 상위 화면의 영향을 검증하지 못했습니다. 사용자 제보 후 별도의 headless Edge 브라우저에서 수동 일정 등록 → 판매건수·매출액 입력 → 상세 매출 기록 클릭으로 오류를 재현했습니다. `salesRecordDialog`가 숨겨진 `settlementWorkspace` 안에서 열려 화면은 보이지 않고 모달의 클릭 차단만 적용되는 배치 오류였습니다.

팝업을 `body` 바로 아래의 공통 영역으로 옮겼습니다. `sales-records.html`은 정산 탭 안이 아니라 `detailDialog` 앞에 삽입해야 합니다. Pages 생성기는 이 위치를 검사하며 잘못된 위치의 빌드를 차단합니다. 수정 후 실제 브라우저에서 팝업 표시, X/바깥 클릭/ESC/돌아가기, 미저장 입력·스크롤·초점·저장된 일정 보존, 모바일 너비에서 표시를 검증했습니다. PHP/JavaScript 문법과 기존 모델 검사도 확인했습니다.

브라우저 회귀 검사는 `tools/test-sales-records-browser.cjs`입니다. Playwright가 제공되는 Node 환경에서 `TEST_BROWSER_EXECUTABLE`(필요 시), `TEST_OUTPUT_DIR`, `TEMP/TMP`를 프로젝트 드라이브로 지정한 뒤 실행합니다. 생성된 Pages 파일을 독립적인 로컬 HTTP 서버와 브라우저에서만 검사하며 외부 요청을 차단합니다. 사용자 브라우저나 회사 운영 DB에는 접속하지 않습니다.

기능 소스는 business-name.js/css, sales-records.js/css/html입니다. 실제 실행 소스는 developer-empty/public/index.php이며 tools/build-pages-preview.py가 docs/index.html을 생성합니다. 로컬 가상 자료·주문 파일·테스트용 저장 엔드포인트는 저장소와 Pages에 포함하지 않습니다.

기준일: 2026-10-14. 현재 구현과 후속 PHP/DB 개발 제안을 구분합니다.

## 실행본과 원본 데이터

03_사내일정관리_시안.html을 브라우저에서 열면 일정표와 분리된 정산 화면을 확인할 수 있습니다. HTML/CSS/JavaScript와 엑셀 처리 템플릿을 포함한 단일 실행 파일이며 아직 PHP 서버나 DB에는 연결하지 않았습니다.

사용자가 적용을 승인한 TimeBlocks CSV 1,679건이 현재 기준 데이터입니다. 원본은 자료/CSV_원본/calendar_import_2023-02-01_2027-01-31.csv에 보존합니다. 실제 기록 범위는 2023-02-10~2027-01-01이며, 2023년 467건·2024년 562건·2025년 425건·2026년 220건·2027년 5건입니다.

32_CSV반영_일정데이터.json과 HTML의 schedules 배열은 동일합니다. HTML이 JSON을 실시간으로 읽지 않으므로 JSON 변경 후에는 재생성이 필요합니다. 기존 이미지 전사 222건은 09_이미지반영_일정데이터.json과 원본 화면에 대조 자료로 보존하며 현재 달력에 중복 합치지 않습니다.

## CSV 추가 반영

‘일정 원본 CSV’ → 선택·미리보기 → 신규/갱신/동일 건수 확인 → ‘일정표에 반영’입니다.

sourceId가 같으면 추가하지 않고 이전 원본과 현재 편집값을 비교합니다. 직원이 직접 편집한 항목은 보호하고 원본에서 바뀐 미편집 항목만 갱신합니다. 판매건수·매출·정산 반영 이력은 보호합니다. 파일에 없는 기존 일정은 삭제하지 않습니다. 잘못된 행은 일부 반영하지 않고 전체 반영을 차단합니다.

상세 컬럼·규칙은 30_일정원본CSV_입력.md를 참고합니다. 최신 제목 형식 분류와 주차별 담당자 상세는 33_공구형식분류_주차별상세.md에 정리했습니다. sourceId는 서버에서도 원본 시스템 식별자와 조합하여 UNIQUE 제약을 두는 것이 좋습니다.

## 전달 구성과 재생성

28_개발자전달_2026-10-14.zip을 통째로 전달하면 실행본·원본 CSV·정규화 데이터·비교 이미지·기능별 소스를 함께 검토할 수 있습니다.

- 03_사내일정관리_시안.html: 현재 실행본.
- 32_CSV반영_일정데이터.json: 현재 1,679건 기준 데이터.

- 09_이미지반영_일정데이터.json, 자료/2026_원본/: 이미지 전사 대조 자료.
- owners.seed.json: 고정 담당자 키·현재 성함·기본색. 브라우저 추가 설정은 포함하지 않음.
- 23_제품명_기준_검토.json, 23_제품명_변경이력.json: 기존 이미지 제품명 정리 근거.

- README_개발자인계.md, SOURCE_MAP.md, quality/, manifest.json: 안내·검사 결과·무결성 목록.

일반 실행에 Python은 필요하지 않습니다. 재생성은 .work/import2026/integrate_import.py를 Python 3 표준 라이브러리로 실행합니다. ROOT는 D:\타임블럭으로 고정되어 있으므로 다른 환경에서는 각 모듈의 ROOT를 같은 프로젝트 폴더로 통일하거나 공통 설정으로 분리해야 합니다. HTML만 수정하면 재생성 시 덮어써집니다.

전달 소스만 별도의 D드라이브 폴더에서 재생성하여 HTML과 두 일정 JSON이 동일한지 검증합니다. 브라우저 프로필·캐시·Git·중간 검증 HTML·구매자 주문 상세를 담은 원본 정산 엑셀은 포함하지 않습니다. 주문 데이터가 없는 엑셀 서식과 정산 구현 소스는 포함합니다.

## 서버 권장 설계 — 후속 개발

1. 담당자: 고정 owner_id, 성함, 기본색, 활성 여부. 퇴사·이름 변경 시 과거 일정 연결을 유지합니다.
2. 일정: 고정 schedule_id와 원본 sourceId, owner_id, 원래 category, 기간·시간, 상품/SKU, 닉네임, 특이사항, 개별색, 판매건수·매출액을 저장합니다. 화면 정렬 순서로 ID를 재부여하지 않습니다.
3. 원문·감사: sourceCsv와 원본 파일 해시, 별도 변경 이력의 수정 전후·수정자·시간을 보존합니다. 원본·사용자 편집 필드를 구분하여 CSV 갱신 충돌을 처리합니다.
4. CSV 이관: sourceId UNIQUE와 트랜잭션으로 전체 검증 후 반영합니다. 승인된 제목 형식으로 유형을 분류하고, 미분류 잔여·담당자 공란·미확정 색상은 별도로 보존합니다.
5. 정산 연결: 자료 식별값·대상 일정·이번 건수/금액/기간·적용자/시간을 별도로 저장하고 트랜잭션으로 중복 합산을 차단합니다.
6. 화면 설정: 직원별 설정과 공용 마지막 월의 정책을 정하여 서버에 저장합니다. 현재 localStorage는 PC 사이에서 공유되지 않습니다.

금액은 원 단위 정수, 판매건수는 정수로 저장하며 NULL과 실제 0을 구분합니다. DB 연결 뒤에는 DB를 기준으로 삼고 요청마다 원본 파일로 덮어쓰거나 재생성하여 운영 데이터를 초기화하지 않습니다.

현재 공휴일 데이터는 기존 구현 범위인 2026~2030년입니다. CSV의 2023~2025년 일정·실제 날짜·요일은 반영했으며, 해당 과거 연도의 공휴일 데이터 추가는 별도 검증 대상입니다.

## 확정된 매출·정산 규칙

- 일정표 판매건수는 취소·입금대기·반품완료 등을 제외한 유효 주문번호의 중복 제거 건수입니다. 판매수량과 구분하고 교환완료는 포함합니다.
- 일정표 매출액은 정산 화면의 주문금액(gross)입니다. 정산 기준 매출(net)·수수료·최종 지급액과 구분합니다.
- 수수료·세금 계산은 정산 기준 매출을 사용합니다. 쿠폰은 별도 차감하지 않습니다.
- 수수료는 파일 선택 전 10/15/20% 중 명시 선택합니다. 일반 개인은 기존 소득세·지방소득세와 세목별 10원 버림, 사업자는 해당 세금 공제만 제외합니다.
- 정산과 일정표는 분리되어 있으며, 미니 달력에서 대상 일정을 선택하고 변경 전후를 확인하여 예를 누를 때만 매출을 연결합니다.
- 여러 정산은 기존 값·이번 값·합계를 확인하여 누적합니다. 아니요는 미니 달력으로 돌아갑니다.
- SHA-256 반영 이력으로 동일 주문 자료를 중복 적용하지 않습니다. 내용이 다른 파일 사이의 일부 주문 겹침을 자동 판정하는 기능은 별도입니다.
- 선택 월에 진행한 공구 또는 공구 시작일 기준으로 집계합니다. 일정 전체 금액을 사용하며 주문일별 금액 분할 기능은 아닙니다.
- 월·주차·제품별 집계와 내보내기는 같은 일정 매출 값을 사용합니다.

## 검증과 연결 순서

실제 CSV 전체 필드·정규화 데이터·HTML을 대조했습니다. CSV 적용 39개, 기존 CSV 읽기 44개, 기존 정산·매출 합산 122개 브라우저 검증과 좁은 화면 확인을 통과했습니다. 제목 분류와 주차별 상세 36개 브라우저 검증도 통과했습니다. 원본 CSV와 이미지 전사 222건은 보존했습니다.

개발자는 HTML 동작·원본/정규화 데이터 검토 → DB 초기 이관 → 일정·추가 CSV 저장 → 새로고침·다른 PC에서 지속성 → 권한·감사 이력 → 정산 합산 중복 차단 순서로 연결할 수 있습니다. 로그인·권한·서버 공유 저장은 후속 개발 범위입니다.

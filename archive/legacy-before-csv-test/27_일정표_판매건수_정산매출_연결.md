# 일정표 판매건수·주문금액 연결과 누적 합산

반영일: 2026-10-13

## 반영 기준

- 판매건수: 취소·입금대기·반품완료 등 제외 내역을 뺀 유효 주문번호의 중복 제거 건수입니다. 교환완료는 포함합니다.
- 일정표 매출액: 정산 화면의 **주문금액**입니다. 취소·반품 차감 전 주문금액을 사용하며, 쿠폰을 별도로 차감하지 않습니다.
- 정산 기준 매출, 수수료, 세금, 최종 지급액은 기존 정산 계산에 사용합니다. 일정표에 가져오는 매출액만 주문금액으로 변경했습니다.
- 판매수량은 판매건수와 구분해 정산 화면에서 유지합니다.

## 반영 및 합산

공구정산 → 엑셀 불러오기 → 일정표 매출 반영하기 → 미니 달력에서 일정 선택 → 확인 → 예

1~15일과 16~말일 등 나눠 정산하는 자료를 같은 일정에 더할 수 있습니다. 기존 판매건수 또는 매출액이 입력돼 있으면 다음 문구로 확인합니다.

> 기존 매출액과 판매건수가 있습니다. 내역을 합산할까요?

확인표에는 기존 값, 이번 정산, 반영 후 합계가 표시됩니다. 예를 누르면 기존 값에 더하고, 아니요는 변경 없이 달력으로 돌아갑니다. 빈 일정도 반영 전 확인을 받습니다. 미입력 항목은 합산 시 0으로 계산하며, 기존에 입력한 0은 기존 값으로 취급합니다.

닉네임 일치 일정은 강조하며 자동 저장하지 않습니다. 상품·기간·담당자와 이번 정산 주문기간을 확인할 수 있습니다. 취소 일정에는 반영할 수 없습니다.

## 중복 방지와 집계

첫 번째 자료와 두 번째 자료의 반영 이력을 모두 유지합니다. 같은 주문 자료를 다시 불러와도 다시 더하지 않으며, 파일명·수수료·개인/사업자 유형을 바꾸거나 일정 총액을 수동 수정해도 반영 자료의 이력을 유지합니다. SHA-256은 동일 주문 행 자료를 식별하며, 일부 내역이 겹치지만 내용이 다른 파일의 중복 주문을 자동으로 판정하는 기능은 포함하지 않습니다.

월·주차·제품별 합계와 매출 내보내기에는 동일한 누적값을 사용합니다. 확인 중 일정이나 정산이 바뀌면 최신 값으로 다시 확인을 받습니다. 합산 후 입력 가능한 범위를 넘으면 저장하지 않습니다. 일정표 연결 이력에는 주문 상세나 구매자 정보를 복사하지 않습니다.

## 검증

브라우저에서 정산 계산·엑셀·상태 분류·수동 반영·합산 관련 122개 항목을 통과했습니다. 추가로 개인/사업자, 수수료 선택, 최초 반영, 합산 확인·완료, 좁은 화면을 확인했습니다.

- 주문금액 450,000원과 정산 기준 매출 150,000원이 다른 자료에서 일정표는 450,000원을 가져옵니다. 정산 수수료·세금은 150,000원 기준을 유지합니다.
- 두 자료 합산 후 월·주차·제품별 합계와 월·주차 매출 내보내기가 동일합니다.
- 합산 거절, 중복 클릭, 첫 자료 재입력, 수동 총액 변경, 미입력·0·부분 입력, 범위 초과, 취소 일정 차단을 확인했습니다.
- 검증용 입력은 테스트 페이지에서만 수행했습니다. 원본 엑셀 두 개와 222개 원본 일정 데이터는 유지했습니다.

## 저장 범위

현재 HTML 시안의 매출과 연결 이력은 열린 페이지에서 유지하며 새로고침 시 초기화됩니다. 서버 공유와 영구 저장은 추후 PHP/DB 연결이 필요합니다. 모든 소스·검증·미리보기 파일은 D 드라이브에 저장했습니다.
